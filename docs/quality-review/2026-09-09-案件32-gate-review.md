## 指摘事項

### 指摘1

- 対象箇所: `GoogleAccountManager.kt:79-80,115`
- 問題: `getCredential()` にApplication contextを渡している。Android公式APIは資格情報UIを同じタスクで起動するためActivity contextを使うよう明記している。
- 影響: 実機で認証UIの遷移が未定義または失敗し、元の「無反応ボタン」が解消しない可能性がある。
- 必要な修正: Application contextは永続化だけに使い、`getCredential()` 実行時は前面Activityのcontext（必要なら `MutableContextWrapper`）を渡す。失敗結果もUIへ通知する。
- 再確認方法: Manager/MainActivity統合テストと実機またはエミュレータで、選択UIの表示と成功・キャンセル・失敗の区別を確認する。

### 指摘2

- 対象箇所: `GoogleAccountManager.kt:135-143`, `SettingsTabScreen.kt:77-85`
- 問題: `signOut()` は定義されただけでUIから到達できず、連携済み行はクリックを無効化している。設計判断4の「ログアウト（連携解除）機能も併せて実装する」を満たさない。
- 影響: 利用者が保存済みの氏名・メールアドレス・画像URLをアプリ内から削除できない。
- 必要な修正: 連携済み行または明示的な解除操作から `signOut()` を呼び、状態と表示を `NotLinked` へ戻す。
- 再確認方法: 連携解除後にSharedPreferencesの3項目が削除され、未連携表示へ戻ることをテストする。

### 指摘3

- 対象箇所: `MainActivity.kt:70-72,87-90`, `GoogleAccountManager.kt:119-124`, `SettingsTabScreen.kt:77-85`, `SettingsTabGoogleAccountLinkJvmTest.kt`
- 問題: UIへ渡すのは `displayName` だけで、`email`、`photoUrl`、`NotConfigured`、失敗結果が消失する。`displayName == null` の正常な `Linked` も未連携扱いになる。全 `GetCredentialException` をキャンセル扱いし、テストは保存・復元・解除・失敗を検証していない。TDDのRED実行記録もない。
- 影響: 仕様の3値が画面に完全に反映されず、状態判定も誤る。設定不備や通信失敗も利用者には無反応に見え、主要回帰をテストが防げない。
- 必要な修正: `GoogleAccountState` 全体または同等のUI stateをsharedへ渡し、連携判定を `Linked` で行う。email/photoUrlも表示し、`NotConfigured`と失敗を区別して通知する。取得・保存・復元・解除・エラー分類をTDDで検証する。
- 再確認方法: 表示名あり/なしの `Linked`、`NotConfigured`、各失敗、保存復元、解除を含むテストと `:app:assembleDebug` を実行する。

## 指摘事項

### 指摘1

- 対象箇所: `web/src/tabs/InputTab.tsx:39-43`、`web/src/App.tsx:33-38`
- 問題: `submitInput`成功後、`InputTab`が結果を保存した直後に`onSubmitted()`が呼ばれ、`App`がホームタブへ即時遷移する。`InputTab`がアンマウントされるため、`post_action.type === 'INSIGHT'`でも気づきカードと4択フィードバックを表示・操作できない。
- 影響: 受入条件の正常系「Insight表示→4択フィードバック→フィードバックAPI送信」がコード上到達不能で、MVPの主要導線を完了できない。
- 必要な修正: 送信成功時はHomeデータの再取得だけを行い、InputTabを表示したまま結果と4択を操作可能にする。必要なら再取得通知と画面遷移を別コールバックに分離する。
- 再確認方法: `submitInput`がINSIGHTを返すケースのコンポーネントテストを追加し、気づきカードと4択が表示され、選択時に`submitFeedback`が正しい`insight_id`と値で1回呼ばれることを確認する。実Geminiキーが利用可能なら同じ導線をE2Eでも確認する。

### 指摘2

- 対象箇所: `web/`のテスト構成、案件11の実装履歴
- 問題: 対象UIの自動テストがなく、Red→Greenの記録もない。今回の到達不能な導線を型チェックとビルドだけでは検出できなかった。
- 影響: Gate 3のTDDとGate 4の関連テストを満たせず、画面遷移を含む回帰が再発し得る。
- 必要な修正: 少なくとも送信成功、INSIGHT表示、4択フィードバック、APIエラー表示、Home再取得を対象にした自動テストを追加する。
- 再確認方法: 修正前コードで主要導線のテストが失敗することを確認し、修正後に全テスト・型チェック・本番ビルドを成功させる。

### 指摘3

- 対象箇所: `web/src/vite-env.d.ts`
- 問題: TASK.mdの対象ファイルに含まれないファイルが追加されており、担当範囲の事前宣言がない。

- 再確認方法: TASK.mdの担当宣言と`git diff --name-status`が一致することを確認する。

- 問題: 実行環境に`GEMINI_API_KEY`がなく、Insight生成からフィードバック送信までの実サービス正常系は未検証。
- 影響: LLM応答を含む統合上の不一致が残る可能性がある。
- 必要な修正: この制約単独はブロッキングにしない。APIキーはクライアントへ置かず、利用可能な安全な検証環境でリリース前に正常系E2Eを行い、既知の制約として継続管理する。
